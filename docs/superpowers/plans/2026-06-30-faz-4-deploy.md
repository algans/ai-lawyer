# Faz 4: Deploy (Kendi VPS) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Deploy dosyaları SSH'tan bağımsız önceden hazırlanır; çalıştırma adımları (Task 6+) kullanıcının VPS SSH erişimini sağlamasını bekler.

**Goal:** Uygulamayı kullanıcının kendi VPS sunucusunda, Docker Compose + Caddy (otomatik HTTPS) ile canlıya almak.

**Architecture:** Production multi-stage Docker imajı (standalone Next.js). VPS'te tek `docker compose up -d` ile Next.js + Postgres + Caddy ayağa kalkar. Caddy reverse proxy + Let's Encrypt SSL.

**Tech Stack:** Docker Compose, Caddy 2, Postgres 16, (opsiyonel) GitHub Actions + SSH, Sentry, /canary.

## Global Constraints

- Üretim sırları sadece VPS'teki `.env` (repoda asla). `.env.example` güncel.
- Postgres verisi adlandırılmış Docker volume'da; `pg_dump` ile günlük yedek.
- SSL otomatik (Caddy + Let's Encrypt); HTTP→HTTPS yönlendirme.
- Deploy dosyaları, SSH erişimi olmadan (yerelde build doğrulanarak) hazırlanır.

### Task 1: Production Dockerfile (standalone)

**Files:**
- Modify: `Dockerfile` (Faz 1'deki dosyaya `builder` + `runner` prod hedefleri ekle)

**İçerik (eklenecek hedefler):**
```dockerfile
FROM base AS builder
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npx prisma generate && npm run build

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
RUN addgroup -S nodejs && adduser -S nextjs -G nodejs
COPY --from=builder /app/public ./public
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/prisma ./prisma
COPY --from=builder /app/node_modules/.prisma ./node_modules/.prisma
USER nextjs
EXPOSE 3000
CMD ["node", "server.js"]
```

**Doğrulama:** `docker build --target runner -t hukuki-prod .` yerelde başarılı.

---

### Task 2: docker-compose.yml (production)

**Files:**
- Create: `docker-compose.yml`

**İçerik:**
```yaml
services:
  app:
    build:
      context: .
      target: runner
    restart: always
    env_file: [.env]
    depends_on: [db]
    expose: ["3000"]
  db:
    image: postgres:16-alpine
    restart: always
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - pgdata:/var/lib/postgresql/data
  caddy:
    image: caddy:2-alpine
    restart: always
    ports: ["80:80", "443:443"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
      - caddy_config:/config
    depends_on: [app]
volumes:
  pgdata:
  caddy_data:
  caddy_config:
```

### Task 3: Caddyfile (otomatik HTTPS)

**Files:**
- Create: `Caddyfile`

**İçerik:**
```

    reverse_proxy app:3000
```

**Not:** `{$DOMAIN}` ortam değişkeninden gelir (örn. `hukukiasistan.com`). Caddy SSL'i otomatik alır/yeniler.

### Task 5: Postgres yedekleme

**Files:**
- Create: `scripts/backup.sh`, `DEPLOY.md`'ye cron talimatı

**İçerik (backup.sh):**
```bash
#!/usr/bin/env bash
set -euo pipefail
STAMP=$(date +%F-%H%M)
docker compose exec -T db pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" \
  | gzip > "/opt/backups/hukuki-$STAMP.sql.gz"
find /opt/backups -name "hukuki-*.sql.gz" -mtime +14 -delete
```

**Cron (DEPLOY.md'de):** `0 3 * * * /opt/app/scripts/backup.sh` (her gece 03:00, 14 gün sakla).

### Task 6: DEPLOY.md — VPS kurulum adımları (SSH hazır olunca)

**Files:**
- Create: `DEPLOY.md`

**İçerik (özet adımlar):**
```markdown
1. VPS hazırlık: Ubuntu, `docker` + `docker compose` kur, firewall 80/443 aç.
2. Repoyu çek: `git clone <repo> /opt/app && cd /opt/app`
3. `.env` oluştur (`.env.example`'dan kopyala, gerçek değerleri gir).
4. DNS: alan adının A kaydını VPS IP'sine yönlendir (Caddy SSL için şart).
5. Migration: `docker compose run --rm app npx prisma migrate deploy`
6. Başlat: `docker compose up -d --build`
7. Doğrula: `https://<domain>/api/health` → {"status":"ok"}, SSL yeşil.
8. Yedek cron'unu kur (Task 5).
```
