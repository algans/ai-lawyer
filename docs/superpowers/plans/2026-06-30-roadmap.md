# AI Hukuki Belge Asistanı — Uygulama Yol Haritası (Roadmap)

> **Spec:** [../specs/2026-06-30-ai-hukuki-asistan-design.md](../specs/2026-06-30-ai-hukuki-asistan-design.md)
> **Tarih:** 2026-06-30

Bu doküman 4 fazın genel haritasıdır. Her fazın kendi detaylı planı vardır. Fazlar sırayla uygulanır; her faz kendi içinde çalışan ve test edilebilir bir ürün üretir.

---

## Faz Bağımlılık Sırası

```
Faz 1 (Çekirdek)  →  Faz 2 (Auth + Ödeme)  →  Faz 3 (Test + KVKK)  →  Faz 4 (Deploy)
   temel motor          para kazanma            yayına hazırlık         canlı
```

Her faz bir öncekinin üstüne kurulur. Bir faz bitmeden sonrakine geçilmez.

---

## Faz 1 — Çekirdek Motor
📄 [2026-06-30-faz-1-cekirdek.md](2026-06-30-faz-1-cekirdek.md)

**Hedef:** Ödemesiz ama çalışan prototip — kullanıcı derdini anlatır, AI belge üretir, bulanık önizleme görür.

**Görevler:**
1. Docker + Next.js + Postgres iskeleti (dev ortamı)
2. Prisma şeması + migration (User, Case, Message, Document)
3. Claude API istemci sarmalayıcısı (Haiku + Opus)
4. AI Adım 1: Sınıflandırıcı (classifier)
5. AI Adım 2: Bilgi toplama (slot-filling)
6. AI Adım 3+4: Belge üretimi + öz-kontrol
7. `/api/chat` rotası (chatbot modu)
8. `/api/generate` rotası (belge üretimi + sunucu-taraflı önizleme kilidi)
9. Chat modu frontend
10. Akıllı form modu frontend
11. Bulanık önizleme + paywall iskeleti (henüz ödemesiz)

**Çıktı:** `docker compose -f docker-compose.dev.yml up` ile localhost:3000'de çalışan, belge üreten uygulama.

---

## Faz 2 — Auth + Ödeme
📄 [2026-06-30-faz-2-odeme-auth.md](2026-06-30-faz-2-odeme-auth.md)

**Hedef:** Para kazanabilir ürün — kayıt/giriş, iyzico ödeme, ödeme sonrası PDF/Word indirme.

**Görevler:**
1. Auth (kayıt/giriş, httpOnly cookie oturum)
2. Payment tablosu + migration
3. iyzico SDK soyutlaması (provider arayüzü)
4. `/api/payment/init` (checkout başlat)
5. `/api/payment/callback` (webhook → belge kilidini aç)
6. Sunucu-taraflı tam-metin kilidi (ödendi kontrolü)
7. PDF/Word üretimi + indirme rotası
8. Belge geçmişi sayfası
9. "Nereye nasıl göndereceğin" rehberi (belgeye iliştirilmiş)

**Çıktı:** iyzico sandbox ile uçtan uca ödeme → indirme akışı çalışır.

## Faz 3 — Test + KVKK + Polish
📄 [2026-06-30-faz-3-test-kvkk.md](2026-06-30-faz-3-test-kvkk.md)

**Hedef:** Yayına hazır ürün — kapsamlı test, yasal metinler, güvenlik sertleştirmesi.

**Görevler:**
1. AI kalite eval altyapısı (altın set + otomatik skor)
2. E2E testleri (Playwright: derdini anlat → önizleme → öde → indir)
3. KVKK aydınlatma metni + açık rıza onayı akışı
4. Sorumluluk reddi (her belgede + üretim öncesi onay)
5. Rate limiting (AI maliyet/kötüye kullanım koruması)
6. Prompt injection koruması
7. Maliyet loglama (token → kârlılık)
8. Genel QA + mobil uyum (/qa skill)

**Çıktı:** Yeşil test takımı, yasal kalkan tam, güvenlik kontrolleri yerinde.

---

## Faz 4 — Deploy (Kendi VPS)
📄 [2026-06-30-faz-4-deploy.md](2026-06-30-faz-4-deploy.md)

**Hedef:** VPS'te canlı.

**Görevler:**
1. Production Dockerfile (multi-stage, optimize build)
2. `docker-compose.yml` (Next.js + Postgres + Caddy)
3. `Caddyfile` (otomatik HTTPS)
4. `.env.example` + ortam değişkeni dokümantasyonu
5. Postgres yedekleme (`pg_dump` cron)
6. `DEPLOY.md` (SSH hazır olunca uygulanacak adımlar)
7. (Opsiyonel) GitHub Actions + SSH deploy otomasyonu
8. Canlı izleme (Sentry + /canary)

**Çıktı:** VPS'te HTTPS ile çalışan canlı uygulama, soft launch'a hazır.

**Not:** Faz 4'ün çalıştırma adımları kullanıcının SSH erişimini sağlamasını bekler. Tüm deploy dosyaları SSH'tan bağımsız olarak önceden hazırlanır.

## Uygulama Yöntemi

Her faz planı `subagent-driven-development` (önerilen) veya `executing-plans` ile, görev görev, aralarda inceleme yapılarak uygulanır. Bir faz bittiğinde sonraki fazın planı bite-sized'a genişletilip uygulanır.
